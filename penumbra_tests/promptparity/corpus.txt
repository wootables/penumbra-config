# =============================================================================
# promptparity corpus - ONE tag, ONE position in the SQL, THREE engines.
#
# Read by test_promptparity.php (the scheduler and ?json=1 engines) and by
# promptparity_browser_tests.js (the browser engine). Line based, no escaping:
#
#   group: <heading>
#   case:  <what this case pins>
#   sql:   the statement, tag(s) included   (\n = a line break)
#   ans:   name=value&name=value            (empty = nothing answered)
#   mode:  dialogs                          (browser only: run with dialogs ON -
#                                            needed for forcedefault=, which the
#                                            browser does not apply with them off)
#   all:   what EVERY engine must emit
#   browser: / runner: / json:              per-engine, where they rightly differ
#
# The browser sends binds (:p1, :p2) plus a parameter list; its half writes each
# bind back in as the quoted literal the PHP engines emit, so one expected line
# serves all three. The only place the engines are ALLOWED to differ is the
# literal that stands for "no answer": NULL (browser bind, scheduler) vs ''
# (?json=1).
#
# Only shapes with ONE right answer that all three engines GIVE live here. Known
# gaps are listed in README section 6, not written down here as "expected" wrong
# output. The one gap left in place ON PURPOSE - no answer + quotes around the
# tag - is pinned per engine at the end of test_promptparity.php instead.
# =============================================================================
