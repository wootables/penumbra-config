## Defects (all three settled the same evening: D1 deployed 21:46 as commit b8540f3; D2 and D3 fixed in the suites, tests only)

**D1 - Ask retrieval cannot find the IP Address List section.** `help_retrieval.php:82` drops every token shorter
than three characters (`if (strlen($w) < 3) continue;`), so "IP" never reaches the scorer, and "list" is in the stop
list (`help_retrieval.php:38`). What is left, "address" and "enforced", must both match a chunk in ask mode, and the
`sec-ip` section (help/topics/saveSecurityHelpLightbox.php:27-28) says "Not in use", "no IP check runs", never
"enforced". The client-side TOC search does find Security & Access for "IP address"; only the Ask/assist retrieval
misses. Fix to consider: let `pnb_help_tokenize()` keep a short allow-list of two-letter tokens (ip, s3, db, pi) -
the same function tokenizes the chunks and the question, so a synonym row alone cannot help while the token never
reaches the index - then rebuild the v2 chunk cache (`prebuild_caches.php v2`), and add a query-side row such as
`'enforce' => array('enforced','enforce','checked','check','use')` so "enforced" can meet the section's own words.

*Resolved 2026-10-17 21:46, commit b8540f3 (a follow-up side session):* `pnb_help_tokenize()` keeps a two-tier allow-list
`PNB_HELP_SHORT` (ip, s3, db, ui, ai for the assistant and the Ask page; pi, id, fy indexed but queried by the Ask page only,
so data questions naming PI / ID / FY still pull no help into the assistant), `PNB_HELP_VER` 6, both caches rebuilt on live.
No synonym row was needed: the question now lands on Security & Access first with the IP Address List passage (suite R8;
R9 pins the assistant, R10 the VER mechanism; mutants `short-tokens-dropped` and `assist-short-leak`). Check 16 re-run in
Chrome at 21:52 after the deploy: the Ask page answered "No, the IP address list is not enforced. The IP Address List field
is disabled, its value is not saved with the report, and no IP check runs ..." from Security & Access (Auditor second),
one model call. Details in the helpv2 README ("Two-letter tokens").

**D2 - sftpkey C8 is a 1-in-256 flake.** `test_sftpkey.php:155` expects `penumbraSchedulerSecretDecrypt($encShared,
$SECRET2) === false`; the helper (`db_connection.php:3951-3955`) returns whatever `openssl_decrypt` returns, and
AES-256-CBC under a wrong key yields a padding-valid garbage string about one time in 256 (the IV is random per
encrypt), so the check goes red by chance - run 1 red, run 2 green on identical live files. Options: assert
`!== $PEM_RSA` (what the test needs), or try a few IVs, or have the helper reject a plaintext that is not text (a
stored key never decrypts to binary) - the last is a code decision. No live effect: the transport only decrypts with
the real key.
**Fixed 2026-10-17 20:48 (follow-up session, test only):** C8 now encrypts under 32 fresh IVs and requires that the
wrong secret never yields the key and normally returns false (`test_sftpkey.php:181`); R4, which drew the same coin,
was de-flaked the same way. Reported by that session: `-Mutants` ALL BITE 5/3/1/2, `-Control` FAIL 1, three plain
runs 79/0 GREEN. From now on a RED sftpkey is real.

**D3 - dropdest's run.ps1 cannot run as a scriptblock.** It ends with `exit $LASTEXITCODE`, which terminates the
calling PowerShell when the body is run through `[scriptblock]::Create(...)` (the only way on this box, since -File on
the UNC share is GPO-blocked): the summary never prints and nothing is logged. Run `php.exe -n test_dropdest.php`
directly, or make the runner print RESULT instead of exiting, as helpv2 and sftpkey do.
**Fixed 2026-10-17 20:53 (follow-up session, test only):** `dropdest\run.ps1` no longer exits; it captures php's exit
code and writes `RESULT: GREEN/RED` with Write-Output (verified in the file). Reported by that session: scriptblock
run 52/0 GREEN, `-Control` RED.

Observations, not defects: the Ask answer on pivot presets stops at the local-storage sentence and omits shared
presets (a model summary of a complete passage); the viz Actions menu shows one item until a chart exists; the hub
